# Bird Classification with YOLO26

Проєкт призначений для бінарної класифікації зображень і відео на два класи: `bird` (птах) та `non_bird` (не птах). Для навчання використовується YOLO26 Classification, а дані отримуються з Hugging Face Datasets із використанням потокового завантаження (streaming).

## 1. Встановлення залежностей

### Вимоги

- Python 3.10 або новіший, сумісний із залежностями проєкту.
- Git.
- Доступ до Hugging Face.
- GPU з підтримкою CUDA рекомендовано для прискорення навчання, але можна використовувати CPU.

### Створення віртуального середовища

Для Windows PowerShell:

```powershell
git clone <REPOSITORY_URL>
cd YOLO26

py -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install ultralytics datasets pillow pyyaml loguru
```

Якщо проєкт використовує `uv` та містить `pyproject.toml`, залежності можна встановити командою:

```powershell
uv sync
```

Для доступу до приватних або gated-датасетів Hugging Face може знадобитися токен. Його потрібно зберігати в змінних середовища або локальному файлі `.env`, який внесено до `.gitignore`. Не додавайте токен до репозиторію.

## 2. Підготовка датасету

Дані отримуються з двох наборів Hugging Face:

- `BIRD_DATASET` — зображення птахів.
- `NATURE_DATASET` — зображення для класу `non_bird`.

Ідентифікатори наборів задаються у файлі `consts.py`.

Для отримання даних використовується `load_dataset()` із параметром `streaming=True`. Це дає змогу читати приклади поступово, без попереднього завантаження всього датасету в пам'ять.

### Класи

| Label | Клас | Опис |
|---:|---|---|
| 0 | `bird` | Зображення птахів |
| 1 | `non_bird` | Зображення без цільового класу птахів |

### Підготовка даних

Після отримання потокових даних зображення конвертуються у формат JPEG і розподіляються за директоріями, які підтримує Ultralytics для задач класифікації.

Очікувана структура:

```text
data/
└── bird_dataset/
    ├── train/
    │   ├── bird/
    │   └── non_bird/
    └── val/
        ├── bird/
        └── non_bird/
```

Цільовий обсяг вибірки становить до 5 994 зображень на клас. Передбачений розподіл — 80% для навчання та 20% для валідації.

Оскільки стандартний інтерфейс `YOLO.train()` не приймає довільний Hugging Face `IterableDataset` безпосередньо як джерело класифікаційних зображень, потокові дані спочатку зберігаються у відповідній структурі каталогів, а потім використовуються для навчання.

## 3. Навчання моделі

Навчання виконується через клас `YoloModelPredict` у файлі `train.py`.

Запуск:

```powershell
python train.py
```

Основні параметри навчання:

| Параметр | Значення | Призначення |
|---|---:|---|
| `epochs` | 50 | Кількість епох навчання |
| `imgsz` | 224 | Розмір зображення для класифікації |
| `batch` | 32 | Кількість зображень у батчі |
| `train_ratio` | 0.8 | Частка навчальної вибірки |
| `img_num_per_class` | 5994 | Цільова кількість зображень на клас |

Використовується класифікаційний checkpoint YOLO26, наприклад `yolo26n-cls.pt`, який задається у `consts.py`.

Після завершення навчання Ultralytics зберігає ваги моделі. Найкращий checkpoint зазвичай доступний за шляхом:

```text
runs/bird_classifier/train/weights/best.pt
```

Фактичний шлях залежить від параметрів запуску та директорії результатів.

## 4. Інференс на відео

Для класифікації відео використовується файл `predict_video.py`. Модель обробляє кадри відео та визначає, до якого класу належить кожен кадр: `bird` або `non_bird`.

Приклад запуску, якщо скрипт підтримує аргументи `--input` та `--output`:

```powershell
python predict_video.py --input input.mp4 --output output.mp4
```

Де:

- `input.mp4` — вхідне відео.
- `output.mp4` — шлях до вихідного відео з результатами обробки.

Для інференсу використовується навчений checkpoint `best.pt`.

**Примітка:** наведена команда передбачає, що `predict_video.py` реалізує обробку цих аргументів і збереження відео саме за вказаним шляхом. Якщо скрипт має інший інтерфейс, команду потрібно адаптувати.

Поточна модель виконує класифікацію кадрів, а не детекцію окремих об'єктів. Вона не повертає bounding boxes навколо птахів. Для виявлення координат птахів на відео потрібна модель object detection, навчена на датасеті з відповідними анотаціями.

## 5. Інформація про датасет

| Параметр | Значення |
|---|---|
| Джерело | Hugging Face Datasets |
| Набір для класу `bird` | `BIRD_DATASET` із `consts.py` |
| Набір для класу `non_bird` | `NATURE_DATASET` із `consts.py` |
| Тип задачі | Бінарна класифікація зображень |
| Кількість класів | 2 |
| Цільовий обсяг | До 5 994 зображень на клас |
| Розподіл | 80% train / 20% validation |
| Формат зображень | JPEG |
| Тип анотацій | Мітка класу на рівні зображення |

### Спосіб підготовки анотацій

Мітки створюються програмно на основі джерела даних:

- зображення з `BIRD_DATASET` отримують мітку `0` (`bird`);
- зображення з `NATURE_DATASET` отримують мітку `1` (`non_bird`).

Для класифікації використовуються мітки рівня зображення. Координати об'єктів та bounding-box анотації не створюються.

### Ліцензія

Ліцензії джерел необхідно перевірити на відповідних сторінках Hugging Face.

- `BIRD_DATASET`: ліцензію потрібно підтвердити.
- `NATURE_DATASET`: ліцензію потрібно підтвердити.

До публікації проєкту необхідно переконатися, що умови обох наборів дозволяють заплановане використання даних. Ліцензія датасетів також відрізняється від ліцензії вихідного коду та базової моделі.

### Динаміка навчання

За графіками навчання спостерігаються такі тенденції:

- `train/loss` поступово зменшується приблизно до 0,008–0,01.
- `val/loss` знижується приблизно до 0,012–0,014 наприкінці навчання.
- `metrics/accuracy_top1` зростає приблизно до 99,7%.
- `metrics/accuracy_top5` залишається на рівні 100%.

Для задачі з двома класами Top-5 accuracy має обмежену інформативність. Основними показниками якості є Top-1 accuracy, precision, recall, F1-score та confusion matrix.

Зниження train і validation loss разом зі зростанням Top-1 accuracy свідчить про успішне навчання на використаних даних. Водночас для перевірки узагальнювальної здатності моделі потрібне незалежне тестування на зображеннях, які не використовувалися для навчання або налаштування.

### Висновок

На наданій валідаційній вибірці модель демонструє високу якість бінарної класифікації: accuracy становить близько 99,71%, а кількість помилок — 7 із 2 397 прикладів. Метрики двох класів збалансовані.

Для підтвердження результатів у реальних умовах необхідно додатково перевірити модель на незалежному наборі даних і відео з різними умовами освітлення, фоном, масштабом та ракурсом.

## 7. Проблеми та можливі покращення

### Проблеми під час реалізації

**1. Потокове завантаження даних**

Hugging Face Streaming дозволяє отримувати дані поступово, але стандартний API навчання Ultralytics не підтримує довільний Hugging Face `IterableDataset` безпосередньо як вхідний класифікаційний датасет. Тому перед навчанням потрібне проміжне збереження зображень у підтримуваній структурі каталогів.

**2. Якість міток**

Автоматичне присвоєння міток за джерелом спрощує підготовку даних, але може призводити до помилок, якщо в наборі `non_bird` є зображення птахів або якщо вихідний датасет має некоректні мітки.

**3. Баланс та різноманітність даних**

Однакова кількість зображень у двох класах не гарантує однакової складності прикладів. Модель може засвоїти особливості фону, стилю фотографій або джерела даних замість узагальнених ознак птахів.

**4. Відеоінференс**

Класифікація кожного кадру не визначає місце розташування птаха. Крім того, передбачення можуть змінюватися між сусідніми кадрами.

**5. Перевірка узагальнення**

Висока validation accuracy не гарантує аналогічної якості на нових даних, особливо якщо навчальна та валідаційна вибірки містять схожі або дубльовані зображення.

### Можливі покращення

1. Перевіряти зображення на пошкодження, дублікати та неправильні мітки.
2. Фіксувати seed, версії бібліотек, параметри навчання та версії джерел даних.
3. Використовувати окрему тестову вибірку для фінального оцінювання.
4. Аналізувати precision, recall, F1-score та confusion matrix окремо для кож
